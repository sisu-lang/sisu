# E0053: call with the wrong number of arguments

A call passes one argument for each parameter of the function or method, and a variant's constructor one for each field of its payload: `Expr.Num(1)`. The array methods `len()` and `sum()` take none and `contains(x)` takes one; a conversion `i64(...)` or `u8(...)` takes one, and so do `panic(...)` and `todo(...)`; `read_line()` takes none.

The error names a method as the receiver's type and the method: `i64.min`, `f64.sqrt`, `string.len`, `[i64].contains`, `Box<i64>.get`. The type is the one that the call has, not the type that the `extend` block writes, so a call on a `[U]` names `[U].contains` and not `[T].contains`. A function has no receiver, and the error names it alone: `add`.

## Why

Sisu has no default values for parameters and no functions that take a varying number of arguments. Each parameter needs its value, and a value with no parameter has nowhere to go.

## Broken

```sisu
fn add(a: i64, b: i64) -> i64 {
    a + b
}

fn main() {
    print(add(1))
}
```

## Fixed

```sisu
fn add(a: i64, b: i64) -> i64 {
    a + b
}

fn main() {
    print(add(1, 2))
}
```
