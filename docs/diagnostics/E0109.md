# E0109: unsupported format spec

Sisu's format specs take `#`, or an alignment (`<`, `>` or `^`), a width and a precision: `{x:#}` or `{x:>8.2}`. The other parts of Rust's and Python's specs are errors: zero padding (`{n:03}`), a sign (`{x:+}`), a type such as `e` or `x`, a fill character before the alignment (`{s:*^9}`), a space (`{ x:>5 }`), and a width or precision taken from a variable (`{x:>{w}}`). A width cannot start with `0`. `#` stands alone: with an alignment, a width or a precision, in any order, as in `{x:#>8}`, `{x:>8#}` or `{x:#.2}`, it is an error too, with its own message: "`#` does not combine with a width, alignment or precision". A `?` alone, as in `{x:?}`, and a `#?` alone, as in `{x:#?}`, are errors too, each with its own help: Sisu has no debug form, so delete the `?`, or write `#` alone to lay the value out over lines. A `#` with a width, an alignment or a precision gets the `#` message also when the width or the precision is over its limit, as in `{x:#2000}`: the limit error ([E0110](E0110.md)) comes after you remove the `#`. The error points at the spec, from its `:`.

## Why

A small spec is quick to read and has one meaning. Each part left out has another way to say it, and there is no single rewrite to offer, so there is no fix. Build the text you need with ordinary code, such as a loop that adds `"0"` for zero padding, or pad to a fixed width.

The `#` flag lays a value out on more than one line. A width, an alignment or a precision changes the text of one line. Sisu cannot tell which one you want, so remove the `#`, or remove the width, the alignment and the precision: write `{xs:#}` or `{xs:>8}`, not `{xs:#>8}`.

## Broken

```sisu
fn main() {
    let n = 7
    print("{n:03}")
}
```

## Fixed

```sisu
fn main() {
    let n = 7
    print("{n:3}")
}
```
