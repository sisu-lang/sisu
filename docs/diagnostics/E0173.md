# E0173: value of a `let ... else` that ends in `}`

The value of a `let ... else` cannot end in `}`. A value that ends in `}` is an `if`, a `match`, a `loop` or a block.

## Why

`let x = if c { a } else { return }` is an `if` expression: the `if` reads its own `else`. For the other values, the parser cannot tell if the `else` after a `}` belongs to the `let` or to a block that the value has. Rust has the same rule. The compiler does not guess: put the value in `( )`, and the `else` is the `let`'s.

The fix puts the value in `( )`. The rule looks only at the last token of the value. A value such as `f(match k { _ => o })` ends in `)`, so it needs no change.

## Broken

```sisu
fn main() {
    let k = 1
    let o: i64? = Some(2)
    let Some(v) = match k { _ => o } else { return }
    print(v)
}
```

## Fixed

```sisu
fn main() {
    let k = 1
    let o: i64? = Some(2)
    let Some(v) = (match k { _ => o }) else { return }
    print(v)
}
```
