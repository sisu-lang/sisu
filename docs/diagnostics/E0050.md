# E0050: a type that cannot be inferred

`None` takes the optional type its position expects. Where nothing says which type, Sisu cannot choose one.

## Why

Every optional is an optional of some type: `None` of `i64?` and `None` of `Tree?` are different values. A `let` with no type has nothing to take it from.

A call of a generic function, class or variant has the same problem when nothing fixes one of its type parameters. `first([])` gives `T` no type: the `[]` has none of its own, and a later use of the result does not count. Annotate the result, `let x: i64? = first([])`, or write the type arguments, `first<i64>([])`.

`Some(None)` has the same problem: `Some` holds a value of any type, and `None` has no type of its own. Annotate the optional, `let x: i64?? = Some(None)`.

`Ok(1)` has the same problem: `Ok` holds the value, and nothing says the type of the error. Annotate the result, `let r: Result<i64, string> = Ok(1)`. `Err("bad")` leaves the type of the value open in the same way.

## Broken

```sisu
fn main() {
    let x = None
}
```

## Fixed

```sisu
fn main() {
    let x: i64? = None
    print(x ?? 0)
}
```
