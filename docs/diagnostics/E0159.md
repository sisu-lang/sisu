# E0159: operator on a type that has none

`==`, `!=` and `contains` need the interface `Eq`, and `<`, `<=`, `>` and `>=` need `Ord`. This error is on an operator whose operands have a concrete type that does not have the interface. The type can lack the interface itself, or a part of it can: `[Node]` has no `==` because `Node` has none. The message names that part.

A built-in type has `Eq` when its parts have it: the numbers, `bool`, `char`, `string`, and the arrays, optionals and enums of types that have it. A class has no `Eq` of its own. Only the numbers, `char` and `string` have `Ord`. A class or an enum gets either interface when its program writes the conformance.

## Why

Two names for one class object are the same object, so the test that a class value supports is `a is b`. Comparing the fields of two objects is a choice that a class makes with a written `Eq`, as it chooses its own order with a written `Ord`. A rule of the language that compared the fields would not know the class's own idea of equality.

For a class, the help shows `a is b`. For a value that holds a class, such as `[Node]`, `is` does not apply: make the class conform to `Eq`. When the type has a conformance whose bounds do not hold, as `extend<T: Ord> Pair<T>: Eq` does for a `Pair<bool>`, a note says which bound fails.

An operator on a type parameter, or on a value that holds one, is [E0139](E0139.md): add a bound to the parameter.

Operands of different types are the mistake, whatever interfaces the types have. That error is [E0047](E0047.md) for `==` and `!=`, and [E0032](E0032.md) for `<`, `<=`, `>`, `>=` and `contains`. An operand that cannot be the type of the other one has the same rule. A number that does not fit is [E0040](E0040.md), [E0042](E0042.md) or [E0104](E0104.md). This error comes when the operands are one type. A `T` beside a `T?` counts as one type. So does an operand whose own error leaves it with no type. An error in an operand that is not about its type, as a wrong `let` in a block, does not hide this error.

## Broken

```sisu
class Node {
    value: i64
}

fn main() {
    let a = Node(value: 1)
    let b = Node(value: 1)
    print(a == b)
}
```

## Fixed

```sisu
class Node {
    value: i64
}

fn main() {
    let a = Node(value: 1)
    let b = Node(value: 1)
    print(a is b)
    print(a.value + b.value)
}
```
