# W0002: variable that is never reassigned

A binding declared with `let mut` must be reassigned somewhere in its scope.
These are reassignments: `=`, a compound assignment such as `+=`, and a write
to one of its elements. A write to a field of a struct, `t.n = 1`, or to a
part of one, such as `t.xs[0] = 1`, changes the binding `t`. The change must
come before a later `let` of the same name in the same scope shadows the
binding. When it never changes, declare it with `let`.

A `mut` parameter is a binding of this kind, and the same rule holds. A call
that passes the parameter `mut` to another function reassigns it. When the
function never reassigns the parameter, its `mut` changes nothing for the
caller. The warning has no fix, because removing the `mut` changes every
caller. A write to a field of a class object is not a reassignment. For a
parameter that holds class objects, the help says that the fields of a class
object change without `mut`. A parameter gets no warning when an interface requirement spells its
`mut`, or when the body of the function is `todo`. A conformance method with a
`mut` that its requirement does not spell gets [E0152](E0152.md) only.

[W0011](W0011.md) warns in place of W0002 when a `while` condition that
nothing in the loop changes reads the binding.

[W0014](W0014.md) warns in place of W0002 for a `let mut` that nothing reads.
W0002 still warns for an unread `let mut` in a function that no live code
uses, or when the program has an error.

## Why

`mut` marks what can change
([ADR 0011](../adr/0011-let-mut-marks-what-can-change.md)). A `let mut` that
never changes would tell the reader to watch for a change that never comes,
so the keyword must always tell the truth.

## Broken

```sisu
fn main() {
    let mut count = 3
    print(count)
}
```

## Fixed

```sisu
fn main() {
    let count = 3
    print(count)
}
```
