# W0014: local or parameter that nothing reads

A `let`, a `let mut`, the name of a `for`, a name that a pattern binds or a parameter is a warning when no expression reads its value, and the program still builds. Only the locals and parameters of live code are judged; live code is as for [W0012](W0012.md). A name that starts with `_` gets no warning, and `self` is never judged. The warning does not show while the program has an error. For a `for` name or a pattern name, the safe fix replaces the name with `_`. A `let` or a parameter has no fix, because only you know if the value is still necessary.

## Why

A name that nothing reads is often a bug: the code computes or receives a value and then does not use it. In the broken program below, `area` takes a height `h` but multiplies the width by itself. These are not reads:

- a write to the name, `x = e`
- a compound assignment, `x += e` or `s += "a"`, which reads the old value only to write it back
- a write to an element, `xs[i] = e`

Any other read counts, also a read inside the value that is written back, as in `x = x + 1`. A field write through a class, `p.x = 1`, reads `p`: it changes a shared object that other code can see. A function or a method with a `todo` gets no warning for its parameters, because they are likely to be used when the body is written. Its locals are still judged. An unread `let mut` gets this warning and not [W0002](W0002.md): delete it, and both go. To keep a name on purpose, start it with `_`.

## Broken

```sisu
fn area(w: i64, h: i64) -> i64 {
    w * w
}

fn main() {
    print(area(2, 3))
}
```

## Fixed

```sisu
fn area(w: i64, h: i64) -> i64 {
    w * h
}

fn main() {
    print(area(2, 3))
}
```
