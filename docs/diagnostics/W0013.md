# W0013: field that no live code reads, or variant that no live code builds

A field of a class that live code builds is a warning when no live code reads it, and the program still builds. A variant of an enum that live code builds is a warning when no live code builds that variant. Live code is as for [W0012](W0012.md). A write to a field, or a `+=` to it, does not read it. `dbg` shows the fields of a class that its operand is, or that the operand holds in an array, an optional or an enum payload. That is not a read: the warning for such a field shows the `dbg` call. `dbg` shows a field that is a class by its name only, and it shows a class with a written `to_string` by its text, so neither shows the fields. `print` and an interpolation show only the name of a class. A `dbg` in dead code does not count. A pattern that names a variant does not build it. A use in dead code does not count, and the warning shows up to three such uses. A class or an enum that nothing builds gets W0012, not this warning. A field whose name starts with `_` gets no warning. The warning does not show while the program has an error. There is no fix, because only you know if the member is still necessary.

## Why

A field that nothing reads, or a variant that nothing builds, is a member that the type carries for nothing. Each object holds the field's value, and each `match` on the enum needs an arm for the variant. But no part of the program uses them. They are often what a refactor leaves behind. A written `eq` reads the fields that it names, as any method does. Delete the member, or read it where the program needs it. To keep a field on purpose, start its name with `_`.

## Broken

```sisu
class Point {
    x: i64
    y: i64
}

fn main() {
    let p = Point(x: 1, y: 2)
    print(p.x)
}
```

## Fixed

```sisu
class Point {
    x: i64
    y: i64
}

fn main() {
    let p = Point(x: 1, y: 2)
    print(p.x + p.y)
}
```
