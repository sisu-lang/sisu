# W0007: unnecessary `;`

A `;` separates two things on one line that would otherwise need a line break between them: two statements, two fields or methods, two variants, or two `match` arms, as in `let x = 2; print(x * 21)`. Most other `;`s are unnecessary. That is a `;` at the end of a line, at the start of one, right after `{`, or before `}` or `else`. It is also a `;` at the end of the file, and every extra `;` in `;;`. A `;` after a top-level function, class, enum or struct is unnecessary too. Such an item needs no separator before the next item. The program still builds. A `;` whose removal would join two lines into one statement stays an error ([E0011](E0011.md)), as at the start of a line before `.f()`. A `;` where something else must come next also stays an error, as in `let x = ;`.

## Why

A line break already ends a finished statement, so a `;` after one is not needed. Reporting it keeps one way to write a program, and the safe fix removes the `;`. There is no fix for a `;` at the start of a line after an unfinished statement, as after `let x =`. Removing such a `;` by hand can also need a change to the line after it. There is also no fix when the file has a syntax error and the fix would change how the file lexes.

A `;` never changes what a block gives. In `let y = { x; }`, `y` is still `x`: the `;` does not turn the block's value into `unit`, as it would in Rust.

## Broken

```sisu
fn main() {
    let x = 1;
    print(x)
}
```

## Fixed

```sisu
fn main() {
    let x = 1
    print(x)
}
```
