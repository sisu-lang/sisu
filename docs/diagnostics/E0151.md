# E0151: inherited interface with a built argument

An interface can inherit a generic interface. Each argument of the inherited interface is a type parameter of the inheriting interface, written alone, or a type that names no type parameter. `interface Feed<T>: Convert<T>` and `interface Fixed<T>: Convert<i64>` are valid. `Convert<[T]>`, `Convert<T?>` and `Convert<Box<T>>` are not.

The argument cannot be an associated type of the interface either, as `interface Feed: Convert<Item>` beside `type Item`. An associated type names `Self`, which is a type built from a type parameter.

## Why

With an argument built from a type parameter, each level of inheritance can double the inherited interfaces of a bound: `I3<T>: I2<[T]>, I2<T?>` gives two copies of `I2`, and `I2` gives two of `I1`, and so on. Sisu keeps the number of inherited interfaces small, so it asks for an argument that has one form only.

## Broken

```sisu
interface Convert<T> {
    fn convert(self) -> T
}

interface Feed<T>: Convert<[T]> {
    fn feed(self) -> T
}

fn main() {
    print(1)
}
```

## Fixed

```sisu
interface Convert<T> {
    fn convert(self) -> T
}

interface Feed<T>: Convert<T> {
    fn feed(self) -> T
}

class Probe: Feed<i64> {
    fn convert(self) -> i64 {
        1
    }

    fn feed(self) -> i64 {
        2
    }
}

fn read<T: Feed<i64>>(item: T) -> i64 {
    item.feed() + item.convert()
}

fn main() {
    print(read(Probe()))
}
```
