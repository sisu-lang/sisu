# E0071: nesting too deep

An expression, type or block nests more than 256 levels deep.

## Why

Every stage of the compiler walks the program as a tree, one level per nested expression, block or type. The limit keeps that walk from running out of stack, and no program written by hand comes near it. A program that reaches it is usually generated; give the nested parts names with `let`, or functions, instead.

A chain is deep too. `a + b + c` is `(a + b) + c`, so each operator in a chain is one level, and so is each call, field or index in `x.f().g()[0]`. A chain of 300 `+` nests 300 levels, though the text has no parentheses. A comparison chain such as `a < b < c` is one level. When the links of a chain are more than half the levels, the report says "this chain makes the nesting deeper than 256 levels". Put a part of the chain in a `let`, and use the name in its place.

A type alias can make a type deeper than the text that writes it. In `type D2<T> = D1<D1<T>>`, each use of `D1` is one level, but `D1<T>` has a level of its own, so the type that `D2` names is twice as deep. The compiler replaces each alias with the type it names, so the limit holds for that type, and the report says "the type that `D9<D9<T>>` names nests deeper than 256 levels". It stands at the first written type that passes the limit, and each alias that uses it is an error without a report of its own. An alias does not make a type shallower, so use a class or an enum to hold an inner part: a class has a name, and its fields are not levels of the type that names it.

## Broken

```sisu
fn main() {
    let b = true
    print(!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!b)
}
```

## Fixed

An even number of `!` cancels out:

```sisu
fn main() {
    let b = true
    print(b)
}
```
