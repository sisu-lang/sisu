# W0011: `while` condition that nothing in the loop changes

A `while` whose condition reads local variables that nothing in the loop changes is a warning, and the program still builds. Parameters, `self` and the names a pattern binds are locals too. The condition can hold literals, `None`, locals, operators, comparisons, `==`, `!=`, `is`, an index and the built-in `.len()`. A call or a field in the condition means no warning, because it can see a change that the loop makes through an object. An `==` or `!=` on a value that holds a class also means no warning, unless the other side is `None`. A condition with no local, such as `1 < 2` or a `const`, does not warn. A `break`, `continue`, `return`, `panic` or `todo` anywhere in the loop means no warning, and so does an error in the loop. There is no fix.

When the warning names a `let mut` that is never reassigned, [W0002](W0002.md) does not warn about it. The fix of W0002 changes `let mut` to `let`, and that keeps the endless loop.

## Why

No code outside the loop can change a local, so the condition has the same value on every pass. The loop either never runs or never ends.

## Broken

```sisu
fn count(n: i64) {
    let mut i = 0
    while i < n {
        print(i)
    }
}

fn main() {
    count(3)
}
```

## Fixed

A loop that you switch off on purpose reads a `const`. A loop that must end changes its condition in the loop.

```sisu
const RUNNING = false

fn count(n: i64) {
    while RUNNING {
        print(0)
    }
    let mut i = 0
    while i < n {
        print(i)
        i += 1
    }
}

fn main() {
    count(3)
}
```
