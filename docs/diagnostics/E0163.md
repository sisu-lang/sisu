# E0163: generic items with too many instances

The generic items of the program have more than 100,000 instances.

## Why

An instance is one copy of a generic item for one list of type arguments. The compiler makes one instance for each list of type arguments that the program reaches. A generic item that uses another generic item twice, each time with different type arguments, makes two instances of the other item for each instance of its own. A chain of such items doubles the instances at each step, so a chain of 17 items makes 2^17 - 1 = 131,071 instances, though no item is large.

The compiler stops when the instances pass 100,000. The label names the generic item that has the most instances at that time, and gives their number so far; the final number can be higher. When your program declares that item, the error is on its name. When the item is in the prelude, as `Result` is, the error is on the part of your program that the compiler was working on when it stopped: an item, such as a function or a class, or an expression. The same limit covers generic classes, enums and functions.

To fix the error, use fewer distinct type arguments, so that two uses in an item make the same instance. Or put a non-generic item in the chain, because a non-generic item has one instance only.

The limit costs little. These numbers are for `sisu build` of a release build, with a chain of generic functions as in the example and `/usr/bin/time -f '%e s %M KB'`. A chain of 16 functions is the largest chain under the limit. It has 65,535 instances, and the build takes 3.9 s and 0.7 GB of memory at the peak. A chain of 17 functions is the first chain over the limit. The compiler stops after 0.23 s and 117 MB, and reports the error. Without the limit, the chain of 17 functions takes 5.9 s and 1.3 GB. The machine had a high load, so the times can be lower on another machine.

## Fixed

```sisu
fn g1<T>(x: i64) -> i64 {
    return x + 1
}

fn g2<T>(x: i64) -> i64 {
    return g1<T>(x) + g1<T>(x)
```
