# E0155: `extend` of a type that is not a class or an enum

An `extend` block adds methods to a class or an enum. It cannot extend a built-in type, such as `i64` or `[i64]`, or a type parameter.

## Why

Only the prelude adds methods to a built-in type. A program that extends one could change what every other program means by `i64`. To add behavior to a number, write a function, or wrap the number in a class. A type parameter stands for a different type at each use, so a block cannot add methods to it. Write an interface for what the type parameter must do, and use it as a bound.

A type parameter of the block must appear in its target, because a call finds the type of the parameter from the receiver. In `extend<T> Meters`, no receiver gives `T` a type. Remove the unused parameter.

A target can have type arguments: `extend<T> Stack<T>` adds methods for every `Stack`, `extend<T> Stack<[T]>` for every `Stack` of arrays, and `extend Stack<i64>` for one `Stack` only. The parameters of the block are the ones that its target names. In `extend<T> Stack<i64>`, the target names no `T`, and the error points at it. When the block uses `T` nowhere else, the fix removes the list of type parameters.

A block cannot name an associated type in its target or in the arguments of its interface, as `extend<S: Source> Wrap<S.Item>` or `extend<S: Source> Peek<S>: Convert<S.Item>`. A call finds the parameters of a block from the type of its receiver, and the receiver does not show which type a parameter stands for when it is written through an associated type. Write the target with a type parameter of its own, such as `extend<T> Wrap<T>`, and give that parameter the bounds that the methods need.

## Broken

```sisu
extend i64 {
    fn double(self) -> i64 {
        self * 2
    }
}

fn main() {
    print(1)
}
```

## Fixed

```sisu
class Meters {
    value: i64
}

extend Meters {
    fn double(self) -> i64 {
        self.value * 2
    }
}

fn main() {
    print(Meters(value: 1).double())
}
```
