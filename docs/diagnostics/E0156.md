# E0156: call that more than one conformance answers

A type can conform to two interfaces that both require a method of one name. A call of that method on a value of the type then has two answers. The compiler picks one when only one answer returns the type that the context expects.

## Why

The type of the context decides, with `let n: string = c.name()`. A call with no expected type, such as `let n = c.name()`, does not decide. Write the type that you expect. If the two answers return the same type, no annotation can tell them apart: call the method through a function with one bound, such as `fn label_of<T: Label>(x: T)`. A method in the body of the class wins over a method of a conformance block.

A method can return a type that names a type parameter of its own. The context cannot choose such a result, unless the call writes the type argument, as in `c.make<i64>(1)`.

A call on a value of a type parameter can have more than one answer too. In `fn show<T: Label & Code>(x: T)`, the call `x.name()` could come from `Label` or from `Code`. The expected type picks one when only one of them returns it, as above. When both return the same type, no annotation can tell them apart. Give the function one bound instead.

## Broken

```sisu
interface Label {
    fn name(self) -> string
}

interface Code {
    fn name(self) -> i64
}

class Circle {
    r: f64
}

extend Circle: Label {
    fn name(self) -> string {
        "circle"
    }
}

extend Circle: Code {
    fn name(self) -> i64 {
        7
    }
}

fn main() {
    let c = Circle(r: 1.0)
    let n = c.name()
    print(n)
    print(c.r)
}
```

## Fixed

```sisu
interface Label {
    fn name(self) -> string
}

interface Code {
    fn name(self) -> i64
}

class Circle {
    r: f64
}

extend Circle: Label {
    fn name(self) -> string {
        "circle"
    }
}

extend Circle: Code {
    fn name(self) -> i64 {
        7
    }
}

fn main() {
    let c = Circle(r: 1.0)
    let n: string = c.name()
    let k: i64 = c.name()
    print(n)
    print(k)
    print(c.r)
}
```
