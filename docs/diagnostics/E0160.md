# E0160: enum payload that is too large

The payload of an enum can be 4 GiB or more. A value of an enum holds the payload of its largest variant inline, and a field of an enum type holds that whole value. A payload must be less than 4 GiB. That is the limit of the language for every alignment. A value of that size can never be on the stack.

The error is on the innermost enum that is over the limit, not on the enums that hold it. They are over the limit too, and one change to the innermost enum fixes all of them. For an instance of a generic enum, the error is on the declaration of the enum, and the message names the instance. A second label marks the first use that makes the instance, when the compiler knows one. The compiler finds the size from an upper bound, so the message says that the payload can be 4 GiB or more. The bound can be a little more than the real size, so the compiler can report a payload that is a little under 4 GiB.

## Why

Each enum field adds the size of its enum to the payload. A chain of enums that each hold the next one several times grows at every step. In the example, sixteen fields at each of seven steps are more than 4 GiB. A value of this size can never be on the stack, so the language does not allow a payload of 4 GiB or more.

A field of a class type or of an array type is a reference. The value it refers to is not part of the payload, so the field adds the size of a pointer only. To fix the error, hold a part of the payload in a class or in an array, as the Fixed example does for `Cell4`.
