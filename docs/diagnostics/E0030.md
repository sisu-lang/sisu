# E0030: type that does not exist

A type is `i64`, `u8`, `f64`, `bool`, `char`, `string`, a class, an enum, a type parameter, an associated type such as `S.Item`, or an array of a type such as `[i64]`, and any of these may be followed by `?`. Any other name is not a type.

When a class, an enum, an interface or a built-in type has a similar name, the error offers it as an unsafe fix. The unsafe fix may be wrong: the name could be a type that was never written.

An associated type is written through a type parameter: `S.Item`, for a parameter `S` with a bound whose interface declares `type Item`. The error is also E0030 when the program cannot write one that way:

- `S` has no bound that declares `Item`. When one interface of the program declares it, the help gives the bound to add, such as `S: Source`. When two bounds of `S` declare it, the error is [E0156](E0156.md).
- The type before the dot is a class, an enum or another type that is no type parameter, as `Countdown.Item`. Inside a class that chooses the type, `Self.Item` is the same error, and the help writes `Item`. A class or an `extend` block writes the type that it chose as `Item` alone.
- The choice of an associated type names an associated type of its own conformance, as `type Item = [Item]`. A choice is a type, so it cannot depend on the choices next to it. Write the type itself. When a class or an enum has the same name, as in `type Item = Item`, the associated type hides it: rename one of them.
- The choice of an associated type leads back to the same associated type of the same type. For `Link<T>`, the choice `type Next = T.Next.Next` of `Link<End>.Next` asks for `End.Next`, which is `Link<End>`, and then for `Link<End>.Next` again. The checker reports the choice once, with the type it found. Write a choice that ends.
- The choice of an associated type needs more than 128 steps to find its type. The compiler follows a choice that names another associated type, then the choice of that one, and so on. Each associated type that it is in the middle of is one step, and it stops at 128 steps. A choice can make a larger type at each step, so that the same associated type never comes again. Then no loop is found, and only this limit ends the walk. A chain that ends within 128 steps is correct. The error is at the choice where the walk stopped. Write a choice that gives its type in fewer steps, or that does not make its types larger. `sisu check` follows a chain only through types that nest up to 128 levels deep, and only for a limited number of associated types for each bound. A program whose types grow in many ways at once can also pass `sisu check`. For these programs, the error comes from `sisu build`, and it can be the loop form above.
- Two bounds of one declaration wait for each other: `fn f<T: A<S.Q>, S: B<T.P>>`. The type `S.Q` holds the arguments of the bound of `S` that declares `Q`, so that bound comes first. A bound that writes `S.Q` waits for the bounds of `S` whose interface declares `Q` or inherits it. A bound gives the declarations that its interface and the interfaces it inherits make, and which ones depend on the names of the interfaces and the text of their arguments, not on their types. So the order does not depend on the order of the parameters. A bound waits for the declarations that the other bounds give, and not for one that only it gives, so `S: Source & Convert<S.Item>` is clean, and `S: Holds<S.Item>` is the first form above. If another bound of the same interface gives a second `Item`, as in `S: Holds<i64> & Holds<S.Item> & Holds<T.Item>`, the error is [E0156](E0156.md). Two interfaces that inherit the same `Item` with the same arguments give one declaration. So `S: Source & First<S.Item> & Second<S.Item>` is clean, because `Source` is in scope. Without `Source`, the two bounds give `Item` only through each other, and they wait for each other. Here the bound of `T` waits for the bound of `S`, and the bound of `S` waits for the bound of `T`. The error is at the associated type of each bound on the loop. Write one of the bounds without an associated type.

## Why

Sisu checks every value against its type, so each type a program names must be one the program can see.

## Broken

```sisu
fn main() {
    let count: Number = 3
    print(count)
}
```

## Fixed

```sisu
fn main() {
    let count: i64 = 3
    print(count)
}
```
