# E0030: type that does not exist

A type is `i64`, `u8`, `f64`, `bool`, `char`, `string`, a class, or an array of a type such as `[i64]`, and any of these may be followed by `?`. Any other name is not a type.

When a class, an enum, an interface or a built-in type has a similar name, the error offers it as an unsafe fix. The unsafe fix may be wrong: the name could be a type that was never written.

An associated type is written through a type parameter: `S.Item`, for a parameter `S` with a bound whose interface declares `type Item`. The error is also E0030 when the program cannot write one that way:

- `S` has no bound that declares `Item`. When one interface of the program declares it, the help gives the bound to add, such as `S: Source`. When two bounds of `S` declare it, the error is [E0156](E0156.md).
- The type before the dot is a class, an enum or another type that is no type parameter, as `Countdown.Item`. Inside a class that chooses the type, `Self.Item` is the same error, and the help writes `Item`. A class or an `extend` block writes the type that it chose as `Item` alone.
- The choice of an associated type names an associated type of its own conformance, as `type Item = [Item]`. A choice is a type, so it cannot depend on the choices next to it. Write the type itself.
- The choice of an associated type leads back to the same associated type of the same type. For `Link<T>`, the choice `type Next = T.Next.Next` of `Link<End>.Next` asks for `End.Next`, which is `Link<End>`, and then for `Link<End>.Next` again. The checker reports the choice once, with the type it found. Write a choice that ends.
- Two bounds of one declaration wait for each other: `fn f<T: A<S.Q>, S: B<T.P>>`. The type `S.Q` holds the arguments of the bound of `S` that declares `Q`, so that bound comes first. A bound that writes `S.Q` waits for the bounds of `S` whose interface declares `Q` or inherits it. A name that an interface declares does not depend on the arguments of a bound. So the order does not depend on the order of the parameters. A bound does not wait for a bound of its own interface, so `S: Source & Convert<S.Item>` is clean, and `S: Holds<S.Item>` is the first form above. Two interfaces that inherit the same `Item` give one declaration. So `S: Source & First<S.Item> & Second<S.Item>` is clean, because `Source` is in scope. Without `Source`, the two bounds give `Item` only through each other, and they wait for each other. Here the bound of `T` waits for the bound of `S`, and the bound of `S` waits for the bound of `T`. The error is at the associated type of each bound on the loop. Write one of the bounds without an associated type.

## Why

Sisu checks every value against its type, so each type a program names must be one the program can see.

## Broken

```sisu
fn main() {
    let count: Number = 3
    print(count)
}
```

## Fixed

```sisu
fn main() {
    let count: i64 = 3
    print(count)
}
```
