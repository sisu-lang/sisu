# E0111: precision on a value that is not an `f64`

A precision in a format spec, `{x:.2}`, sets the number of decimals of an `f64`. Any other value has no decimals, so a precision on it is an error. The error points at the spec, from its `:`.

## Why

An `i64`, a `u8`, a `bool`, a `char` and a `string` have no decimals to round. Rust takes a precision on a string to cut it short, and Python rejects it on an integer; Sisu gives it the one meaning. For an `i64`, the fix converts the value with `f64(...)`, which never fails; beyond 2^53 it rounds to the nearest `f64`. Any other type gets no fix: remove the precision, or convert the value yourself.

An optional has no decimals either, because it can be `None`. A precision on an `f64?` gives this error and no [W0015](W0015.md), and the help says to give a default with `??` first. It writes the example with your part and your spec: `{price:8.2}` gives `{price ?? 0.0:8.2}`. A part that is not a name, a field, a call or an index gets parentheses in the example. A precision on any other optional gives the error with no help. A width or an alignment on an optional is not an error, and it gets the warning W0015.

An `any` value has no decimals either, whatever its interface: the value inside may be a class or a number, and the precision belongs to the type that the program names. It gets this error and no fix.

## Broken

```sisu
fn main() {
    let n = 7
    print("{n:.2}")
}
```

## Fixed

```sisu
fn main() {
    let n = 7
    print("{f64(n):.2}")
}
```
