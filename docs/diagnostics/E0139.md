# E0139: operator on a value of a type parameter

An operator on a value of a type parameter `T`, or of a type that holds one, can need a bound. This error is for a comparison that a bound on `T` can give. It is also for the arithmetic operators `+`, `-`, `*`, `/` and `%`, and for a unary `-`, which no bound gives. `Eq` gives `==` and `!=` on `T`, and on an array, an optional or an enum that holds a `T`, as `[T]` does. `Ord` gives `<`, `<=`, `>` and `>=` on `T` itself. A `contains` on a `[T]` is [E0154](E0154.md), not this error: the prelude writes it for an element that conforms to `Eq`.

A bound on `T` cannot fix a part that fails by itself. An example is an enum with a `T` and a `Node` that has no `Eq`. That error is [E0159](E0159.md), whatever the order of the parts.

Comparing an optional with `None` is allowed: on a `T?` or a `[T]?`, `x == None` and `x != None` test only whether a value is there, and need nothing from `T`. Comparing the values inside, as `x == y` on two `T?` does, needs `T: Eq`.

## Why

`T` may stand for any type, and not every type has every operator: a class has no `<`, and an array has no `+`. A bound says that a type conforms to an interface, and the interfaces `Eq` and `Ord` give the operators. A generic function can use only what its bounds give.

Operands of different types are the mistake, whatever bounds the types have. That error is [E0047](E0047.md) for `==` and `!=`, and [E0032](E0032.md) for `<`, `<=`, `>`, `>=` and `contains`. An operand that cannot be the type of the other one has the same rule. A number that does not fit is [E0040](E0040.md), [E0042](E0042.md) or [E0104](E0104.md). This error comes when the operands are one type. A `T` beside a `T?` counts as one type. So does an operand whose own error leaves it with no type. An error in an operand that is not about its type, as a wrong `let` in a block, does not hide this error. When this error comes, the help shows the bound to add. It keeps the bounds that `T` has: `T: Display` gets `T: Display & Ord`. The help names a type parameter only. A class `Box<T>` has no `==` of its own, so a bound on `T` does not give one: that is [E0159](E0159.md), and `Box<T>` must conform to `Eq`. The same holds for any other part of the operand that is not a type parameter. A comparison that the type does not have for any `T` is not this error. It is [E0159](E0159.md). For example, `<` on a `[T]`, a `T?` or a `Result<T, i64>` is E0159, because an array, an optional and a `Result` have no `<`, and no bound on `T` gives one.

## Broken

```sisu
fn smaller<T>(a: T, b: T) -> bool {
    a < b
}

fn main() {}
```

## Fixed

```sisu
fn smaller<T: Ord>(a: T, b: T) -> bool {
    a < b
}

fn main() {
    print(smaller(1, 2))
}
```
