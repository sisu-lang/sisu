# W0012: function, method, class, enum, struct, interface, `extend` block or constant that no live code uses

A function, method, class, enum, struct, interface, `extend` block or constant that no live code uses is a warning, and the program still builds. Live code is `main`, each function, method and constant whose name starts with `_`, and all the code that live code calls or names.

- A function or a method is used when live code calls it.
- A class or a struct is used when live code builds it.
- An enum is used when live code builds one of its variants.
- A type that names a class, an enum or a struct does not use it.
- A constant is used when live code or a live constant names it.
- An interface is used when live code names it in a bound, or in a bound of the type parameters of a live `extend` block. It is also used when live code calls a method that meets one of its requirements.

A used interface uses the interfaces that it names. These are an inherited interface, an interface in the bound of a requirement, and one in the bound of its own type parameters. An alias body that writes an associated type, such as `S.Item`, uses the interface that declares it, also when nothing uses the alias. Live code also uses an interface when it names it in an `any` type, also through a type alias. This also holds in these places:

- the type of a parameter or a return;
- the type of a field or a payload of a class, an enum or a struct that live code builds;
- the type of a parameter or a return of a requirement of a used interface;
- an associated type that a conformance of such a type chooses.

A conformance alone does not use an interface, because it dispatches nothing. A use in dead code does not count, and the warning shows up to three such uses.

An `extend` block is live when one of its methods is live. It is also live when it declares a conformance for a class, an enum or a struct that live code builds. A dead `extend` block of such a type gets a warning that names the block: delete it. A call of one of its methods in dead code does not make it live, and the warning shows up to three such calls. Its methods get no warning of their own. A block has no name, so `_` cannot keep it; name one of its methods with `_` to keep the block.

A method of a class, an enum or a struct that nothing builds gets no warning of its own. The type gets the warning. When you delete such a type, delete its `extend` blocks with it. A dead method of a live block gets its own warning.

A name that starts with `_` gets no warning. The warning does not show while the program has an error, because a use in code that fails to check can be missed. There is no fix, because only you know if the code is still necessary.

## Why

Dead code is often what a refactor leaves behind. It costs time to read and to keep up to date, and it can make a reader think that a path still runs. Only a use in live code counts. When `old_report` is the only function that calls `format_row`, and nothing calls `old_report`, both are dead. Each one gets its own warning, and the warning for `format_row` shows the call in `old_report`. Delete both, or name `old_report` `_old_report` to keep it on purpose: then `format_row` is live too.

## Broken

```sisu
fn old_report() {
    print("report")
}

fn main() {
    print("done")
}
```

## Fixed

```sisu
fn main() {
    print("done")
}
```

## An `extend` block

The block of `Crate` below has two methods, and nothing calls them. `Crate` is built, so the warning names the block, and the two methods get none. The interface `Shape` is used only in the bound of the block, so it gets a warning too. The label shows the bound once, not once for each method. Delete the block, and then `Shape`.

```sisu
interface Shape {
    fn area(self) -> f64
}

class Crate<T> {
    item: T
}

extend<T: Shape> Crate<T> {
    fn one(self) -> f64 {
        self.item.area()
    }

    fn two(self) -> f64 {
        self.item.area() * 2.0
    }
}

fn main() {
    let c = Crate(item: 1)
    print("{c.item}")
}
```
