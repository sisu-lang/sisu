# E0034: name defined twice

Functions, classes, enums, interfaces and constants share one namespace. The fields and methods of a class share one, and so do the variants and methods of an enum. The labels of one variant's fields share one of their own, so two variants can use the same label. Each name is defined once in its namespace. The prelude functions `print`, `eprint`, `panic` and `read_line` are built in, so no function, class or constant can take their names.

The requirements of an interface and of the interfaces it inherits share one namespace too. An interface that declares a requirement again, when an interface it inherits has the same name, is reported: the inherited interface already requires it, and the secondary label points to that requirement.

The methods of a class or an enum, and the methods of its plain `extend` blocks (`extend Circle { ... }`), share one namespace with its fields or variants. The methods of an `extend Circle: Shape` block belong to that conformance, so they can share a name with a method of the class.

## Why

A call or a type that names a duplicate could mean either definition. Sisu keeps the first and reports the second.

## Broken

```sisu
fn double(n: i64) -> i64 {
    n * 2
}

fn double(n: i64) -> i64 {
    n + n
}

fn main() {
    print(double(2))
}
```

## Fixed

```sisu
fn double(n: i64) -> i64 {
    n * 2
}

fn main() {
    print(double(2))
}
```
