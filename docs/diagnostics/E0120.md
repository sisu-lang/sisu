# E0120: variant or method used as the other

The methods of a struct or an enum are called on a value, `e.eval()`. The variants of an enum are built through the enum, `Expr.Num(1)`. A method named through its type, or a variant called on a value, is an error.

## Why

Sisu has one way to build a variant and one way to call a method. So `Expr.eval` never reads as a function value, and `e.Num(1)` never reads as a method. The error names the form that works.

A call such as `Expr.eval(e)` has a fix when its first argument has the type. The fix moves that argument before the `.`: `e.eval()`. It is safe when the method takes the other arguments. It is unsafe when one of them does not fit, or stands at a `mut` parameter and has no `mut`. It is also unsafe when the method has type parameters of its own, as in `Tree.gm(t, 1)` for `fn gm<U>(self, u: U)`.

Any other form has no fix, since the value to call the method on is yours to choose. That is, the first argument has another type, is optional or has `mut`, or the call has a label, a type argument or no argument.

## Broken

```sisu
enum Expr {
    Num(i64)
}

fn make(e: Expr) -> Expr {
    e.Num(1)
}

fn main() {
    match make(Expr.Num(0)) {
        Num(n) => print(n)
    }
}
```

## Fixed

```sisu
enum Expr {
    Num(i64)
}

fn make(e: Expr) -> Expr {
    match e {
        Num(n) => Expr.Num(n + 1)
    }
}

fn main() {
    match make(Expr.Num(0)) {
        Num(n) => print(n)
    }
}
```
