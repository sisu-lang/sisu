# E0047: comparison of values of different types

Both sides of a comparison have one type. A `T` may stand beside a `T?`, and nothing else is compared across types. This holds for type parameters too: a `T` beside a `U`, or beside a number, is this error, with or without the bound `Eq`. The missing `==` is [E0139](E0139.md) only when both sides are one type. Equality and ordering comparisons between a `u8` and an `i64`, or between a `char` and an integer, report [E0032](E0032.md) instead. So does an ordering comparison of a `string` or a `char` with another type.

## Why

A comparison of an `i64` with a `bool`, or of two different classes, can never be true. Sisu reports it instead of answering `false`.

## Broken

```sisu
fn main() {
    print(1 == true)
}
```

## Fixed

```sisu
fn main() {
    print(1 == 1)
}
```
