# E0043: expression without a value

An expression whose value is used must have one. An `if` without an `else`, whose branch has a value other than `unit`, has none. An expression that never finishes, such as an `if` whose branches all `return`, has none either. Nor has a bare `break` in a `loop` whose other `break`s give it a value other than `unit` or `unit?`.

A `unit` value, such as the result of a call of a function that returns nothing, is a value. It fits where no type is expected, such as in `let u = g()` and `print(g())`. Where a type is expected, it fits only `unit`, `unit?` or a type parameter of the called function. Arithmetic, `-`, conversions and conditions do not take it. Where another type is expected, the error says that the called function returns `unit`. Where `unit?` is expected, an `if` without an `else` has no value, as where another optional type is expected.

For a string literal, the error underlines the first part of the literal that never finishes.

## Why

A `let`, an argument, an operand or a condition needs a value to work with. Nothing is left to bind when the expression never returns, or when it is an `if` with no value. A `unit` is a value of the wrong type where another type is expected.

## Broken

```sisu
fn greet() {
    print(1)
}

fn main() {
    let x: i64 = greet()
    print(x)
}
```

## Fixed

```sisu
fn one() -> i64 {
    1
}

fn main() {
    let x = one()
    print(x)
}
```
