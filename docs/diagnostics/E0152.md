# E0152: conformance that a type does not meet

A class or an enum conforms to an interface when it lists the interface after its name (`class Circle: Shape`), or when an `extend Circle: Shape` block names it. The type then holds every requirement of the interface, as a method with the same signature.

## Why

A conformance is a promise: each function that takes any `Shape` can call `area` on the type. A missing method breaks the promise. A method with another parameter type or another return type breaks it too. The method must have the same parameter types and the same return type as the requirement, with `Self` as the conforming type. It must have the same number of type parameters of its own, with the same bounds. The parameter names can differ.

A requirement can be an associated type. A conformance meets `type Item` with a choice, `type Item = i64`, in the body of the class or in the `extend` block, and the help writes `type Item` for each one it lacks. A choice for a name that no interface of the conformance declares is an error too, such as `type Item = i64` in a block for an interface with no `Item`. The chosen type must meet the bounds that the interface gives its associated type ([E0154](E0154.md)).

In an `extend Circle: Shape` block, every method is a requirement of `Shape`. A method that is not a requirement belongs in `extend Circle { ... }`, or in the body of the class. The body of a class that lists an interface holds the methods of the interface and the methods of the class. A listed interface also needs the requirements of the interfaces it inherits.

## Broken

```sisu
interface Shape {
    fn area(self) -> f64
}

class Circle: Shape {
    r: f64
}

fn main() {
    print(Circle(r: 1.0).r)
}
```

## Fixed

```sisu
interface Shape {
    fn area(self) -> f64
}

class Circle: Shape {
    r: f64

    fn area(self) -> f64 {
        3.0 * self.r * self.r
    }
}

fn main() {
    print(Circle(r: 1.0).area())
}
```

## Generic interfaces

For an interface with type parameters, the help writes each requirement with the type arguments of the conformance. With `interface Convert<T> { fn convert(self) -> T }` and `extend Meter: Convert<i64> {}`, the requirement is `fn convert(self) -> i64`. The arguments also stand in the bounds of the requirement's own type parameters: for `fn mix<U: Convert<T>>(self, other: U) -> T` and `extend Meter: Mix<i64> {}`, the requirement is `fn mix<U: Convert<i64>>(self, other: U) -> i64`. A type parameter of the requirement takes a new name when an argument or a parameter of the block has its name: for `extend<U> Box<U>: Mix<U> {}` the requirement is `fn mix<U2: Convert<U>>(self, other: U2) -> U`, because `U` in the block is another type.
