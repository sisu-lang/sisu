# W0015: optional that `print` or an interpolation may write as `None`

The warning is for an optional that `print`, `eprint` or an interpolation writes as text. An optional can be `None`, and then the program writes the word `None`. The program still builds. The warning is at the optional itself. The message names it with its path (`name`, `user.name`). When the optional has no path (`find()`, `xs[0]`), the message says "this value".

## Why

A program that writes `Hello None` has a bug that no error shows. The warning is there so that you choose what the program writes when the value is missing. Three fixes are possible:

- Unwrap the optional with `if let`, and write only when the value is there.
- Give a default with `??`.
- Call `to_string()` on the optional, to write `None` on purpose.

An optional that sits inside another value gets no warning. An array of optionals, the payload of an enum and the optional inside an optional all print the way their code reads (`[1, None]`). A call of `to_string()` does not warn either. A generic function that prints a value of type `T` does not warn, also when `T` is an optional where it is called.

A precision on an optional is not a warning. It is the error [E0111](E0111.md).

## Broken

```sisu
fn main() {
    let name: string? = "Sisu"
    print("Hello {name}")
}
```

## Fixed

```sisu
fn main() {
    let name: string? = "Sisu"
    print("Hello {name ?? "friend"}")
}
```
