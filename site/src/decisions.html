The values behind the choices

Sisu's goal is that people are productive in it because things work. Four values serve that goal, and a choice that trades one for another follows this order.

  1. Correctness

    The language makes wrong programs hard to write. Mistakes are caught early, at compile time where possible.

  2. Simplicity

    Few concepts, rules without special cases, every effect visible where it happens.

  3. Readability

    Code that reads top to bottom. Errors in plain words.

  4. Performance

    Native code with predictable memory. Optimizations never change what a program means.

Simplicity ranks above readability because agents now write and read much of the code. Special cases and two ways to do one thing cause their mistakes, and slow a human reviewing their work.

Principles

Some records settle features that are still planned, such as generics. The status page shows what works today.

  • 0004Python syntax, Rust semantics, Swift memory modelSurface syntax follows Python, semantics follow Rust, and memory management and everyday ergonomics follow Swift.
  • 0027What Sisu is forproposedFast, small, reliable command-line tools, scripts and server-side software, with code that is fast and easy to verify; three acceptance programs define 1.0.
  • 0006Correctness, then simplicity, then readability, then performanceA design choice that trades one value for another follows this order.

Syntax and names

  • 0001Statements end at newlines, not semicolonsA line break ends a statement, except inside parentheses. No statement ends with ;.
  • 0015The prelude holds only what almost every program usesA name is visible in every file without an import only if almost every program uses it, or the language depends on it.
  • 0019Enums are values named through their enumAn enum is an inline value built as Expr.Num(2); a pattern can use the bare name, and match must cover every variant.
  • 0020Labels belong to the declarationA variant labels every field or none, and is built with its labels in declared order.

Values and change

  • 0002Bindings are immutable by defaultsuperseded by 0011let made a binding that cannot change and var one that can; immutable by default still holds.
  • 0011let mut marks what can changeOne word, mut, marks every binding, field and method receiver that can change.
  • 0007Arrays are values, shared until writtenBinding, passing or storing an array behaves as a copy, made only when a shared array is written.
  • 0022Classes compare by identity plannedA class has no == unless it conforms to Eq by hand; is asks whether two references are the same object.

Memory

  • 0005Memory is managed by reference countingEvery heap object carries a count of its references and is freed when the count reaches 0.
  • 0008Weak references break cyclesA weak mut field does not keep its object alive, and reads as None once the object is gone.
  • 0012Methods borrow selfproposedA method receives self without changing its count, and the caller keeps it alive for the call.
  • 0021A loop makes its written arrays unique before it startsA loop that writes a local array makes it unique once, before the first iteration, so its writes skip the count check.

Types

  • 0014Strings are UTF-8 valuesamended by 0016 and 0018A string is always valid UTF-8 and behaves as a value, and len() counts bytes.
  • 0017Floats follow IEEE 754f64 arithmetic never panics: division by zero gives infinity or NaN.
  • 0018A conversion that can fail returns an optionalu8(n), char(n) and i64(x) of an f64 return an optional, and no conversion panics.
  • 0023Generics are monomorphized and checked at the definitionEach list of type arguments gets its own compiled copy, and a generic body is checked once, against its bounds.
  • 0024Optionals nest plannedi64?? is its own type, and ?? and if let peel one layer.

Errors and diagnostics

  • 0003Integer overflow panics instead of wrappingOverflow, division by zero and dividing the smallest i64 by -1 stop the program with a panic that names the source location.
  • 0013Diagnostics have stable codesEvery error and warning has a code that is never reused, one wording, and an explanation that a test compiles.

Runtime, I/O and concurrency

  • 0009The runtime owns I/O; Sisu builds its own objectsOnly the runtime calls the operating system, and text crosses the boundary as a pointer and a length.
  • 0016The word functions trust the UTF-8 invariantIn a release build, the runtime functions behind words() skip the UTF-8 check that a debug build still makes.
  • 0010Tasks share no objectsproposedA value that crosses into another task is copied; only channel and task handles are shared.

What Sisu deliberately avoids

These come from the roadmap's Deliberately avoided list.

  • Lifetimes and a borrow checker. Reference counting keeps Sisu in Swift's ergonomic camp.
  • Header files.
  • Unrestricted operator overloading.
  • Inheritance. A class is a reference type, not a hierarchy; composition, enums and interfaces cover polymorphism, as in Rust and Go.
  • comptime and macros. Generics and interfaces cover the same ground, and errors stay plain when type checking does not depend on running code.
  • Runtime reflection. Avoided for the same reason as macros, and because it costs at run time.
  • Variadic parameters. An array costs two characters, sum([1, 2, 3]), and uses a type that already exists.
  • Pointers in Sisu code. A class is already a reference, and arrays are values.
  • Formatter options. One style ends style debates.
  • A separate linter. Lints are compiler warnings.
  • import *. A reader must always see where a name comes from.
  • A pipe operator |> and function captures. Method chains and continuation lines already do this, and two ways to write one call break "one obvious way".
  • Gleam's use. Gleam needs it because it has no early return; Sisu has return.
  • Separate float operators such as +.. The checker knows each operand's type, so + serves both.
  • Integers without a size limit, or division by zero that gives 0. Sisu's fixed-size integers panic on overflow and on a zero divisor.
  • Mutable memory shared between tasks. Tasks share no objects, so counts stay non-atomic and Sisu code cannot have a data race (ADR 0010, proposed).
  • A package registry, for a long time. A registry means hosting, security and name squatting.

Interfaces and generic code are planned. Planned work has no promised date and may change.
