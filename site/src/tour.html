Hello and printing

A program starts at main. print writes one value and a line break. Statements end at the end of the line; a ; puts two on one line.

Braces inside a string insert a value. After a colon comes a format spec: an alignment (<, >, ^), a width in characters and a number of decimals. The spec # lays a value out on several lines when it does not fit on one line. Compile with target/debug/sisu build hello.sisu, then run ./hello.

let and let mut

let binds a name that cannot be reassigned. let mut binds one that can. Types are inferred.

A class object works differently. Its fields can change only if the field itself is declared mut, whatever binding holds the object. Objects are shared, so the field decides, not the binding.

Writing p.name = "Eino" in the same program is the same error, E0001, with the help line {{help ../crates/sisuc/tests/diagnostics/E0001-field.err}}.

Functions and if

A function names the type of each parameter and of its result. The last expression in a body is its value. if is an expression too, so it can be a function's result or the right side of a let.

Loops

for walks a range or an array. 0..3 leaves out its end and 0..=3 includes it. while loops on a condition, and break and continue work in both. loop runs until a break. A loop with no break never ends, so a function can return from inside it with nothing after it. while true works the same, but warns and points at loop.

break in a loop can carry a value, which is the value of the loop. A name before a loop is a loop label: break outer and continue outer leave or restart that loop instead of the innermost one.

Optionals instead of null

Sisu has no null. A value that may be missing has an optional type, such as i64?, and is either a value or None. An i64? is not an i64: x + 1 on one does not compile, so you deal with None before you use the value.

You unwrap an optional in one of these ways:

  • a ?? b gives the value, or b when a is None. b may be panic("why").
  • if let x = a runs its block with the value bound to x; while let loops while there is one.
  • let x = a else { return 0 } binds x for the rest of the block, and runs its else block when a is None. That block must leave: it ends in return, break, continue or panic. A pattern also works, as in let Circle(r) = s else { return 0.0 }.
  • a?.field and a?.method() reach through an optional and give an optional.
  • a?.field = v writes the field only when a holds a value. When a is None, v does not run.
  • match a with the arms Some(x) => and None => handles both cases. i64? is short for Option<i64>, an enum that every program has.

return, break and continue are expressions of type never, so they can stand on the right of ??: sum = sum + (o ?? continue) skips a None.

A conversion that can fail returns an optional instead of panicking. i64(41.5) is None, because 41.5 is not a whole number.

Classes

A class declares its fields one per line and its methods after them. A method takes self and may write any mut field. Objects are freed by reference counting when the last reference goes away.

let b = a does not copy the object: a and b hold the same counter, so both ticks count. is asks whether two references hold the same object.

A class has no == of its own. a == b on two objects is an error unless the class conforms to Eq and writes an eq method. is is the identity test.

Enums and match

An enum lists its variants, and each variant can carry data. match takes a value apart, one arm per line, and gives a value.

A value is built through its enum, as in Shape.Point. A pattern uses the bare name, Point, because the type of the matched value tells which enum it is from. A qualified pattern works too.

Generics

A function, a class or an enum can take type parameters in angle brackets. Stack<T> holds values of any one type. The compiler makes one copy of the code for each type argument that the program uses, so a generic call costs the same as a plain one.

The body of a generic function is checked once, where it is written. So it can use only what every type has. A bound asks for more: T: Ord lets largest use >, and a call with a type that has no order does not compile. i64, string and char have Eq and Ord with no declaration.

Most type arguments come from the call: largest([3, 9, 4]) gives i64 for T. An empty array tells nothing, so Stack<string>(items: []) writes the type argument.

Interfaces and any

An interface lists method signatures. A class or an enum conforms to it after its name, and writes the methods. A type that conforms to several interfaces lists them with commas, as in class Tree: Display, Eq. A bound joins them with &, as in T: Shape & Ord.

any Shape is the type of a value of any type that conforms to Shape. One array can hold a Circle and a Rect, and a call on each element runs the method of the type that the value has. The value carries a table of its methods for this. An object is its own data. Any other value, such as the enum below, goes into a counted box first.

An any Shape conforms to Shape, so total takes the [any Shape] as it takes a [Circle].

Not every interface can be any. Eq cannot, because eq takes another value of the same type, and two any values may hold different types. An any value has no ==. An optional does not convert to a bare any Shape: unwrap it first, for example with ?? or a match. The type of an optional any value is (any Shape)?, with the parentheses.

Arrays are values

Assigning an array, or passing it to a function, behaves as a copy. No other holder can change your array. The copy is made only when one holder writes, so reading or passing an array never copies it.

A function cannot change an array that it gets, but a mut parameter lets it change the array of its caller. The call writes mut too, so a reader sees which arguments change. A function can also return a new array. Shared data that changes in place belongs in a class.

An array grows with push. After let mut xs = [1, 2], xs.push(3) makes xs hold three elements. Another holder of the old array keeps its two.

A range index takes part of an array: xs[1..3] is the elements at 1 and 2, xs[2..] runs to the end, and xs[1..=3] includes the element at 3. The result is an ordinary array that shares the elements of xs, so the index copies nothing. A write to either array copies first, as for any shared array. A range that is out of bounds stops the program. xs.get(i), xs.first() and xs.last() give an optional instead.

Integers panic on overflow

Integer arithmetic that overflows stops the program with a panic that names the line. Arithmetic never wraps silently. Division by zero panics the same way, and every panic exits with status 101.

Strings

A string is always valid UTF-8, and it is a value like an array. len() counts bytes, and there is no s[i]. s[a..b] is the part of the string between two byte positions, and it shares the bytes of s; s.get(a..b) gives None where that would stop the program. To work on text, take it apart with chars(), bytes() or words(), and build it back with string(cs).

A char is one Unicode scalar value. The string has 10 of them in 14 bytes, because each ä and ö takes two bytes.

What is not here yet

Sisu is early, and much of an everyday language is still missing. Some of what is planned:

  • weak fields, which do not keep an object alive next
  • Closures and function types next
  • Iterator methods, such as map and filter planned
  • Structs, named arguments and default arguments planned
  • Modules planned
  • Errors with Result and ? planned

Planned work can change and has no promised date. The status page lists what works today, what comes next and what is planned.
